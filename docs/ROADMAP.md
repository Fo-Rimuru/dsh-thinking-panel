# 路线图 / 待办

这里放**已经确认要做、但排在下一个版本**的条目。写进仓库而不是留在聊天里，
是为了让下一个接手的人（包括未来的作者）能直接看到上下文和依据。

## 0.2.0 计划

### 1. 提示词注入做成可选开关

- **现状**：Host 半部**无条件**注入推理语言规则（`systemPrompt.section(10300)` + `context(130)`），
  所以中文提问会跟随中文思考。
- **要改**：设置里加开关，**默认打开**（保持现有行为）；关掉后完全不注入，回到出厂的英文思考。
- **为什么**：有人就是要默认的英文思考（部分任务上英文推理更稳），不该被插件单方面改掉。

### 2. 设置里加「自动更新」开关

- **现状**：`auto-update` 路由已经在 Host 侧实现（`index.js`），但客户端没有入口；
  `holdVersion` 防回退循环只服务于手动路径。
- **要改**：设置行加开关，打开后插件在 DSH 启动时静默检查并安装新版本（沿用现有的
  预检 + 备份 + 原子替换 + 回滚）。

### 3. 图形化的一键回退入口

- **现状**：`rollback` 路由和按钮都已存在，但它和「有新版本可装」挤在同一行里，语义不显眼。
- **要改**：做成独立、醒目的入口，并显示「当前版本 → 将回到的版本」。

### 4. 把插件设置独立成设置左侧导航的一项

- **现状**：设置行挂在 `settings.general.item`（「通用设置」页里的一行）。
- **要改**：改成左侧导航里**独立的一项**。
- **动手前必做**：先导出一次槽目录（`Slots.listSubTree`），确认是否存在
  `settings.section` / `settings.page` 之类的挂载点 —— 这一步别凭猜，
  插件现有的三个槽位都是先探目录才敢写的。

### 5. 自定义 HTTP 端点补「两端一致」的行为测试

- **为什么**：0.1.1 里「检查更新」报 **HTTP 405** —— 客户端按「有没有传 body」决定 GET/POST，
  把 `check`（变更类、但不需要参数）发成了 GET，而 Host 侧把 `check` 列为变更类、一律要求 POST。
  两端各写各的策略集合，**没有任何测试覆盖「客户端真实发出的 method 能否被 Host 接受」**，
  所以只在用户点击时才炸。
- **要改**：mock `fetch`，对每个按钮断言它真实发出的 method + body 能通过 Host 的策略表；
  或者更进一步，把策略收敛成**单一事实来源**（Host 导出一份方法表，客户端只读它）。

## 已完成

- **0.2.1** —— 四个新功能 + 实测与审查挖出来的修复
  - **思考中显示已用时间**：用出厂的 `data.time`
    （`settled?.time ?? state.firstVisibleTime ?? …`，流式期就有），所以**不自己计时** ——
    只在 running 时开一个每秒的定时器算差值。文案是「深度思考中（已用时 N 秒）」
  - **设置页「自检」**：官方组件可用性、渲染/降级计数、自动展开成功与放弃次数、
    导航图标补丁状态、兼容性提示数 —— 样式哪天悄悄变回出厂，一眼就能看出是哪一环掉了
  - **「回到底部」按钮**：只在没贴底时浮在面板右下角（长推理翻上去后不用一路拖回来）
  - **思考预览行数可配**：自绘滑动条，1–20 行、步长 1、拖动即时生效（走 `:root` 的 CSS 变量）
  - **设置页整块空白**：`if (state === null) return null;` 之后又写了 3 个 hook → React #310
    （hooks 数量变化）。已把 hook 全部移到提前返回之前，并加了 `SectionBoundary` 把错误显示到页面上
  - **思考内容只剩一行**：排版容器用了 `flex + gap`，flex item 的 `min-height:auto`
    把 5 行滚动预览压成 1 行 → 改回 block + 相邻兄弟 margin
  - **插话后界面停在上一段**：真因是**面板长高**越过了 DSH 的 25px 跟随阈值
    （`useScrollFollow(state.followingTail, 25)`），此后连 steering 都不再滚
    （出厂源码 4979 行：`… && reading.followingTail`）。现在每次内容变化都顺手把外层带到底。
    前两轮修的都是「展开过程组」，方向错了
  - **设置导航图标**：DSH 的导航图标是 shell 里 `navIcon(id)` 的硬编码映射，第三方一律兜底齿轮
    → 用 DOM 补丁克隆插件自己的 `IconThink` SVG 替换原图标（卸载时还原）
  - **`useTurnData` 从 `useMemo` 内提到组件顶层**：它内部是 `useSyncExternalStore`，
    放在提前 return 之后同样会触发 #310（与设置页同一个病根）
  - **自动更新遇到开发目录只提示不自动装**：本机是 `link:` 安装，`packageDir` 就是工作区源码目录，
    否则一发版就会覆盖未提交的改动
  - 其余：mode 落盘改原子写且失败可见、`rollback` 补 semver 校验、
    `Switch` 写入中禁用、复制按钮的 Enter 不再被标题行抢走、
    `alive` 在 StrictMode 下复位、导航补丁死代码清理……

## 待定位：插话后界面不自动跟随

**现象**（作者报告，可复现但不稳定）：插件流式输出时插一句话，新一轮开始后**主界面不跟到底部**、
停在上一段，要手动拉一次。触发时「几乎一瞬间就有一堆内容出现」，且**发生在思考链里**。

**已经排除的方向**（都试过，相关代码已撤销，不要重走）：

1. ~~展开过程组导致高度突变~~ —— 展开只发生一次，而问题在持续输出时才出现；
2. ~~沿 `parentElement` 找可滚动祖先~~ —— 那**确实是**个 bug（先撞上过程组自己的
   `[data-step-process-body]`，把组体滚到底、外层纹丝不动），但与现象无关；
3. ~~面板长高越过 DSH 的 25px 跟随阈值~~（`useScrollFollow(state.followingTail, 25)`）——
   机制上说得通，但见下：真正的麻烦是「插件自己去滚」这件事本身；
4. ~~插件侧主动写外层 `scrollTop`~~ —— **这条路是错的，已整段撤销。**

**为什么「插件自己滚」走不通**（代码审查对照出厂源码的结论）：

- 出厂有完整的滚动策略层：`useChatReading` / `ChatViewport` / `ScrollFollow` / `useProcessScroll`；
- `ChatViewport.readScroll()` 判定 `movedByReader` **只看位置差是否 > 0.5px，不区分程序化写入** ——
  插件写 `scrollTop` 会被记成「用户自己滚的」；
- `ScrollFollow.sample()` 只在 `movedByReader && !animating` 时更新跟随意图；
- DSH 有在飞的平滑目标时，插件这一写会让它在 `scrollend` 判出「偏离目标 > 25px」→
  **主动释放跟随**，并通过 `stopPreserving()` 打掉分页锚点。

**下一版该走的方向**：不要直接改滚动位置，而是**发出语义意图**
（复用出厂的 `followTail` / `ScrollFollow.owners` 路径）；或者干脆向 DSH 提 issue ——
「贴底时内容长高导致失跟」看起来像**出厂的判定阈值过严**。

**方法学教训**：这一条修了五轮，前四轮都在「猜哪里长高了」，而答案一直在出厂的 `ScrollFollow` 里。
**先读源码，再动手。**

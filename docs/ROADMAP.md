# 路线图 / 待办

这里放**已经确认要做、但排在下一个版本**的条目。写进仓库而不是留在聊天里，
是为了让下一个接手的人（包括未来的作者）能直接看到上下文和依据。

## 0.2.0 计划

### 1. 提示词注入做成可选开关

- **现状**：Host 半部**无条件**注入推理语言规则（`systemPrompt.section(10300)` + `context(130)`），
  所以中文提问会跟随中文思考。
- **要改**：设置里加开关，**默认打开**（保持现有行为）；关掉后完全不注入，回到出厂的英文思考。
- **为什么**：有人就是要默认的英文思考（部分任务上英文推理更稳），不该被插件单方面改掉。

### 2. 设置里加「自动更新」开关

- **现状**：`auto-update` 路由已经在 Host 侧实现（`index.js`），但客户端没有入口；
  `holdVersion` 防回退循环只服务于手动路径。
- **要改**：设置行加开关，打开后插件在 DSH 启动时静默检查并安装新版本（沿用现有的
  预检 + 备份 + 原子替换 + 回滚）。

### 3. 图形化的一键回退入口

- **现状**：`rollback` 路由和按钮都已存在，但它和「有新版本可装」挤在同一行里，语义不显眼。
- **要改**：做成独立、醒目的入口，并显示「当前版本 → 将回到的版本」。

### 4. 把插件设置独立成设置左侧导航的一项

- **现状**：设置行挂在 `settings.general.item`（「通用设置」页里的一行）。
- **要改**：改成左侧导航里**独立的一项**。
- **动手前必做**：先导出一次槽目录（`Slots.listSubTree`），确认是否存在
  `settings.section` / `settings.page` 之类的挂载点 —— 这一步别凭猜，
  插件现有的三个槽位都是先探目录才敢写的。

### 5. 自定义 HTTP 端点补「两端一致」的行为测试

- **为什么**：0.1.1 里「检查更新」报 **HTTP 405** —— 客户端按「有没有传 body」决定 GET/POST，
  把 `check`（变更类、但不需要参数）发成了 GET，而 Host 侧把 `check` 列为变更类、一律要求 POST。
  两端各写各的策略集合，**没有任何测试覆盖「客户端真实发出的 method 能否被 Host 接受」**，
  所以只在用户点击时才炸。
- **要改**：mock `fetch`，对每个按钮断言它真实发出的 method + body 能通过 Host 的策略表；
  或者更进一步，把策略收敛成**单一事实来源**（Host 导出一份方法表，客户端只读它）。

## 已完成

- **0.1.1**
  - 自动展开过程组（默认打开）+ 设置行第二个开关
  - README 修正「工作步骤展示」相关论断（改设置项确实会决定你能不能看到面板）
  - README 图片改用绝对地址（npm 页面不解析仓库相对路径）

- **0.1.2** —— 代码审查后的第一批修复（清单见 [`代码审查-0.1.1.md`](代码审查-0.1.1.md)）
  - **HTTP 405**：客户端按「有没有传 body」决定 GET/POST，把变更类的 `check` 发成了 GET
  - **耗时改为读出厂的 `finalNode.timing`**：原先用模块级 Map 按 node key 记账，而 key 只在会话内唯一，
    两个会话的 `1:1` 会互相污染；顺带干掉了「在 render 里写外部状态」和 LRU 淘汰
  - **`interrupted` 状态**：思考被中断时显示「已停止」+ 出厂同款徽标，而不是「已思考（用时 N 秒）」
  - **自动展开失败后会重试**：effect 依赖只有 `[autoReveal, running]`，不重试就等于这一轮彻底放弃
  - **`mode: off` 不再吃掉自更新入口**：端点注册从 off 短路之后挪到了前面
  - **自更新加了并发互斥**：桌面端与 Web GUI 同时点「更新」不会再交错写文件
  - **体积上限改成流式判定**：原先读完整个响应才判大小，上限形同虚设
  - **自更新面板的重入守卫与卸载保护**
  - **流式尾部判定**改用「后面还有没有正文块」（末块是图片时不再把「思考中」显示成「已思考」）

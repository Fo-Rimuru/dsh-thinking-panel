# 0.1.1 代码审查（2026-10-13）

**方法**：作者自查 + 两个独立审查者 —— 一个只看 `client.js` 的健壮性与性能（不看背景材料），
一个把插件对**出厂接口**的假设逐条回查 `ui-chat-client.js`（会话 UI 的打包产物）。

**结论先行**：插件的**核心假设全部成立** —— 注入的 props 字段名与形状、`blocks` 形状、
`[data-step-process-body]` / `[data-step-process]` / `button[aria-controls]` 三处 DOM 契约、
以及「组体上的 `beforematch` → `reveal()` → `setOpen(true)`」这条揭示通道，全部能在出厂源码里
逐行对上。也就是说「自动展开过程组」的机制基础是实的，不是猜的。

**没有一条属于「插件读错了出厂字段」**。下面都是插件自己这边的疏漏。

---

## 一、确认的 bug（用户可见）

### 1.1 `interrupted` 被当成已结算 · 中

出厂把「被中断」当作独立状态：

```js
6006: interrupted: data.status === "interrupted",
5960: interrupted && … && jsx("span", { className: AssistantMarkdown_module_css_default.stopped, children: t("message.stopped") })
```

插件只判 `data.status === 'running'`（`client.js`），于是 `interrupted` 落进「已结算」分支 ——
思考面板显示 `已思考（用时 N 秒）`，而**不是**「已停止」。佐证：插件的字典里
`'think.stopped': '已停止'` **从未被使用**（死文案）。

**改法**：识别 `interrupted`，头部显示「已停止」，并在正文后补出厂同款的小徽标。

### 1.2 耗时按 node key 记账 → 跨会话互相污染 · 中

`timings` 是模块级 Map，键取 `node.key`，而 `node.key` **只在会话内唯一**
（出厂 `chatNode()` 的 key 就是 `"${turn}:${step}"`）。同一个 DSH 实例里开两个会话，
两边的 `1:1` 会共用一条记录：`noteRunning` 见到已有 `start` 直接返回、`noteSettled` 见到已有 `ms`
也直接返回 → **后一个会话永远显示前一个会话的耗时**。

**改法**：key 里带上会话标识（拿得到的话），或者改成「组件挂载时本地起表 + 模块级仅作跨挂载兜底」。

### 1.3 `pathImages.resolve` 没走出厂的鉴权文件路由 · 中

出厂实现：

```js
5899: return { resolve: (value) => localPathMediaUrl(document.baseURI, value) };
114:  function fileMediaUrl(base, path) { … return new URL(`api/file?path=${encodeURIComponent(path)}`, base).href; }
```

插件直接 `new URL(decoded, document.baseURI)` —— 对绝对本地路径**不会**改写成
`api/file?path=…`，而 `https:` 之类出厂会拒绝的值反而原样返回。
后果：消息里的本地图片可能加载不出来。

### 1.4 自动展开失败后不再重试 · 中

`client.js` 的自动展开 effect 依赖 `[autoReveal, running]`，而 `revealed.current` 只在**成功**时置位。
如果第一次调用返回 `false`（`Event` 不可用、组体那一刻还没带上 `hidden`、DOM 结构不匹配），
之后 `running` 不变 → **effect 不再跑 → 这一轮彻底不展开**。

**改法**：失败后按 rAF/超时重试有限次，或把「未成功」计入依赖。

### 1.5 `mode: off` 会把自更新面板一起关掉 · 中

`index.js` 的 `apply()`：

```js
const text = reasoningLanguageRule(mode);
if (text === null) return;          // ← off 时直接返回
…
registerUpdateRoutes(ctx);          // ← 于是这里永远不执行
```

用户在 `cordis.patch.yml` 里把 `mode` 设成 `off`（只想关掉语言注入）时，
`/dsh-thinking-panel/update/status` 变成 404 → 客户端整块静默隐藏 → **自更新入口消失**。
现在默认值是 `auto`，所以还没人踩到；但 ROADMAP 第 1 条（把注入做成开关）会直接踩上去。

### 1.6 「回滚」重启之后是空操作 · 中

`rollback()` 的默认目标是 `runningVersion`，而它是**进程启动时**读到的版本：

- 装 0.1.0 → 自更新到 0.1.1（文件已换，进程里仍是 0.1.0）→ 点回滚：下载 0.1.0 覆盖 → **正确**；
- 重启后（`runningVersion` = 0.1.1）→ 再点回滚：下载 **0.1.1 覆盖自己** → 提示「已回滚到 0.1.1」，
  实际什么都没回退。

这正是「想要一个真正的一键回退」的根源。**改法**：记住 `previousVersion`，回滚默认回到它，
并在 UI 上显示「当前版本 → 将回到的版本」。

### 1.7 `status.hasUpdate` 忽略 `holdVersion` · 低-中

`check()` 里 `hasUpdate` 会扣掉被 hold 的版本，`status()` 里**没有**。回滚之后面板仍会显示
「→ vX」和「更新」按钮 —— 等于把用户刚关上的逃生门又打开。

### 1.8 自更新没有并发保护 · 中

`applyPayload()` 会先 `rmSync(backupDir)` 再逐个写。桌面端与 Web GUI 同时开着时，
两处同时点「更新」会交错执行（备份目录被前一个删掉、文件写一半）。

**改法**：`createSelfUpdater` 内加一个 in-flight 互斥，并发调用直接返回
`{ ok: false, error: '另一个更新正在进行' }`。

### 1.9 `maxBytes` 限制形同虚设 · 中

```js
const buf = Buffer.from(await res.arrayBuffer());   // 先整个读进内存
if (buf.length > maxBytes) throw …                  // 再判大小
```

**改法**：用 `res.body` 的 reader 流式累计，超限立即 abort。

### 1.10 `other` 块传错 payload · 低

出厂传的是 `block.block`（`other` 包装体里的真实载荷），插件传整个 `block`；
顺带丢了出厂的 `truncatedLabel`，标签还是硬编码英文 `Unknown block`。

### 1.11 `ThinkingBoundary` 失败后不重置 · 中

`failed` 一旦为 `true` 就永不复位：一次瞬时异常（半截 block、循环引用）之后，
即使数据恢复正常，那条消息也**永久只剩纯文本**。

### 1.12 `fileMentions` 少一道出厂守卫 · 低-中

出厂只在「收尾那一节点」解析文件提及：

```js
5984: if (tail?.closing?.finalNode.seq !== data.finalNode.seq) return void 0;
```

插件复刻了 `turn.status === 'closed'` 与 `finalNode` 两道，**漏了 `tail` 这一道**；
而同一个节点会以 `reasoning` / `response` 两种 groupPart 各渲染一次 → 会对非收尾步骤也解析。

### 1.13 `UpdateRow` 的并发与卸载 · 中

- 无卸载保护：`await` 之后仍会 `setBusy` / `setNote` / `setState`；
- `disabled` 要等重渲染才生效 → 快速双击可并发两次 `install`（就是 1.8 的触发路径之一）；
- `await call('status')` 失败会走 `catch`，把刚显示的「已更新成功」覆盖成错误文案。

## 二、观感 / 一致性缺口（对「像官方」这个卖点重要）

### 2.1 缺出厂的排版容器 · 中

出厂 `AssistantMarkdown` 外面套了两层：

```js
5955: jsx("div", { className: …root, "data-streaming": streaming || void 0, children: jsx("div", { className: …body, … }) })
5859: .root{font-size:var(--dsh-content-font-size,14px);line-height:calc(24px + …);color:var(--dsw-alias-label-primary);flex-direction:column;display:flex}
      .body{flex-direction:column;gap:16px;display:flex}
```

插件返回裸 `Fragment` → **既没有字号/行高/正文色基线，也没有 16px 块间距**。
多块消息的行距与段间距会和出厂不一样。

### 2.2 缺「运行中」的无障碍朗读 · 低

出厂在运行中会输出一段 visually-hidden 文本（`t("row.running")`，5838 行），屏幕阅读器能听出来在思考。
插件的头部只有视觉呈现。

### 2.3 `hidden` 属性晚一帧 · 低

出厂用 `useLayoutEffect` 设/清 `hidden`（1601-1610），并**无条件**注册 `beforematch` 监听（1611-1618）；
插件把两者合并进一个 `useEffect`、且只在 hidden 时注册 → 折叠时可能闪一帧，展开期间监听不在位。

### 2.4 `-16px` 负边距的作用域 · 存疑

出厂把它限定在 `.body > [data-turn-process-inline][hidden]`（父级是有 `gap:16px` 的 flex 容器）；
插件写成了全局选择器，而插件的渲染树里并没有那个 flex 父级 —— 该负边距补偿的对象不存在。
**后果需要运行时确认**（是否会通过外边距折叠把后续流项上移 16px）。

### 2.5 `interrupted` 之外的 `data-*` 差异 · 低

插件缺 `data-streaming` / `data-expanded` / `data-preview`。出厂打包产物内部没有 JS 查询它们，
所以对观感影响有限，但第三方样式按出厂属性选择会失配。

## 三、性能与健壮性

| # | 问题 | 为什么 |
|---|---|---|
| 3.1 | `ThinkingPanel` 里 `typeof useDisclosure === 'function' ? useDisclosure() : null` 是**条件调用 hook** | props 变化时会触发 hook 数量变化并崩溃。正解：在父层按 props 选择**渲染**两个 hook 序列固定的子组件 |
| 3.2 | 跟随滚动的 effect **没有依赖数组** | 每次 render 都写 `scrollTop` 并读 `scrollHeight`（强制同步布局）。加 `[text, expanded, running]` 即可 |
| 3.3 | `ResizeObserver` 随 `text` 变化反复创建销毁 | 流式期间每秒几十次。应在挂载时建一次 |
| 3.4 | `reveal` 的 `useCallback` 依赖 `turnProcess` 对象 | 流式期间引用常变 → `beforematch` 监听反复摘挂、`hidden` 属性反复重设 |
| 3.5 | `running && i === last` 用「全局末块」判断是否在思考 | 末块是图片时，真正的 reasoning 块 `i < last` → 流式期间标题错显「已思考」 |
| 3.6 | `tr` 的兜底 `(k) => k` 每次 render 新建 | `labels` 的 `useMemo` 失效 → 子组件 memo 全部击穿 → 流式全量重渲染 |
| 3.7 | `markProgrammatic` 只靠 rAF 复位 | 窗口不可见时 rAF 暂停，标志会一直为 `true`（可用 `setTimeout` 兜底） |
| 3.8 | `timings` 按插入顺序淘汰 | 长时间 running 的记录可能被新 key 挤掉，之后重新开表 → 该步耗时被重置 |
| 3.9 | 未知 kind 走 `JSON.stringify` | 循环引用 / BigInt 会抛错，被 boundary 吞掉后整条消息降级为纯文本 |
| 3.10 | 兜底渲染不检查 `block.text` 类型 | 非字符串会抛「Objects are not valid as a React child」，且异常在 boundary 内部抛出 |
| 3.11 | 焦点还原依赖 `document.activeElement` | 它为 `body` 时 `focus()` 无效，而出厂组头会 focus 自己 → 输入框失焦、焦点跳到组头 |
| 3.12 | `renderMessageImages` 失败静默 | `catch {}` 里连一行 `console.warn` 都没有，图片整组消失且无从排查 |

## 四、功能改进候选

已经在 [`ROADMAP.md`](ROADMAP.md) 里的：

1. 提示词注入做成开关（默认开）
2. 设置里的「自动更新」开关（Host 侧 `auto-update` 路由已存在，缺客户端入口）
3. 一键回退入口（根因见 §1.6）
4. 插件设置独立成设置左侧导航的一项（动手前先导出槽目录）
5. 自定义端点补「两端一致」的行为测试（405 的根因）

本次审查新增的候选：

6. **思考耗时持久化** —— 现在 `timings` 只在内存里，重载后历史消息的「已思考（用时 N 秒）」全没了
7. **展开状态持久化** —— 现在展开态跟着 Turn 重置，重载即回到折叠
8. **思考内容复制按钮** —— 官方 Markdown 有复制，思考面板没有
9. **`compatReport` 让用户看得见** —— 现在只打控制台，用户只会觉得「样式没变」

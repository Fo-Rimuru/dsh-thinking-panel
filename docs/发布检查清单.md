# 发布检查清单

> **约定（2026-10-13）**：每个版本发布前，**先由作者在本机实测一遍，确认没问题再发**；
> 作者要是忘了，Agent 要**主动提醒**。
>
> 为什么要有这条：0.1.1 → 0.2.0 那一轮里，「设置页整块空白」和「输出途中插话后界面停在
> 上一段」两个问题都是**发出去之后**才被发现的 —— 而它们在本机重载一次就能看出来。

## 一、发之前

1. Agent 说清楚这一版改了什么，并请作者按下表实测；
2. 作者实测；
3. 通过 → 发；任何一项不通过 → **先修，不发布**。

## 二、作者要测的（本机是 `link:` 安装，重载 DSH 即可）

- [ ] **设置 → 插件 → 深度思考面板**能打开（入口在「插件」页里；设置左侧导航**不该**再有它）
- [ ] 打开后是**五个开关 + 预览行数滑动条 + 自检区块 + 更新块**，**不是一片空白**
- [ ] 自检那五行在正常状态下都显示**「正常」**（只有出问题时才给数据并标红）
- [ ] 发一条会思考的消息：思考链**不用点就出现**，展开/折叠、复制按钮正常
- [ ] **输出途中插一句话**：新一轮开始时界面**自动跟到底部**（不用手动再拉）
- [ ] 设置页里点「检查更新」**不报错**（0.1.1 曾报 HTTP 405）
- [ ] 关掉再打开「自动展开过程组」，确认开关真的生效

## 三、发的时候

- [ ] `node tools/verify.mjs` 全绿
- [ ] `node tools/test-self-update.mjs` 全绿
- [ ] `package.json` 版本号已提
- [ ] README / README.en.md 的自检数字与新版本一致
- [ ] `git push` **并且** `git push origin v<x.y.z>` —— ⚠️ 普通的 `git push` **不会**推 tag

**推完 tag 就结束了** —— GitHub Actions 会自动：校验 tag 与版本号一致 → 跑两套测试 →
发布到 npm（`--provenance` 附来源证明）→ 建 GitHub Release。
**不需要**真 TTY、不需要 pnpm、也不需要作者点任何认证（走 npm Trusted Publishing / OIDC）。

- [ ] 发布后用 API 验证（不要只看页面）：
      `registry.npmjs.org/dsh-thinking-panel` 的 `dist-tags.latest` 是否为 `x.y.z`、
      有无 `dist.attestations`（来源证明）、
      `api.github.com/repos/Fo-Rimuru/dsh-thinking-panel/releases/tags/v<x.y.z>`
- [ ] CI 绿（`api.github.com/repos/.../actions/workflows/publish.yml/runs`）

> 完整流程与踩过的坑见 `~/.dsh/插件发布流程.md`。
> ⚠️ 改了 workflow 必须**重打 tag**（CI 跑的是 tag 指向的那个 commit 里的 workflow）。

## 四、发之后

- [ ] 提醒作者：`link:` 安装的那份已经是新代码，别人要升级则走自更新（设置页 → 检查更新）
